# 被动订单成交模拟审查

**日期：** 2026-08-09
**更新：** 2026-08-10；接受原始快照约束作为模型边界
**范围：** 受支持的生产重放被动做市路径，以及驱动兼容性回测及其所报告订单成交的实际原始 tick 文件（位于 `E:\FinData\HFT\ticks`）

## 决策

现有数据源被接受为一份**五档快照与累计流量数据契约**。它不是交易所成交流水（trade tape），且缺少逐笔成交 ID、主动方（aggressor）方向与真实接收时间戳，这是该数据集的一个**永久性模型边界**，而不是拒绝该数据集或要求一个不可获得的替代数据源的理由。

因此，恰当的被动成交解读是一个确定性的**快照区间队列代理（snapshot-interval queue proxy）**：

- 队列推进由每个原始累计成交量与成交额区间、依据一个已声明的价格分配规则推断得出；
- 所有原始字段保持完整，且每个推导出的区间都关联到其来源文件与行序号；
- 结果在此固定数据与模型约定下，仅适用于策略之间的比较；
- 一次成交并不断言某一具体交易所订单、或该策略本身，在实盘中一定会成交。

这一放宽适用于原始数据要求，而非生产证据边界。`RawSnapshotAdapterConfig` 现在创建不可变的 `SnapshotInterval` 输入，`PassiveMatchingService` 从其已声明的共享桶中签发独立类型的 `SnapshotIntervalQueueProxyEvidence` 记录。原始快照约定绝不会被传入 `PassiveTrade`，一个推断出的区间桶也绝不会被重新标记为观测到的主动方成交。

`backtest.py`、`market.py` 与 `public_tools/` 仍为冻结的兼容性路径。接受它们的原始数据假设并不会追溯地使其结果成为 S0 证据。未来受支持的快照桥接可以使用同一已声明的模型族，但必须保留受支持路径：

```text
strict loader with snapshot adapter -> CausalIngress -> ProductionReplayAdapter
-> DualBookFoundation -> matcher-issued snapshot-proxy evidence
-> calendar EOD -> PnL attribution -> canonical + research telemetry
```

## 实际原始数据契约

被检查的文件使用同一份通用 schema：

```text
timestamp, exchtime,
bidpx4/bidvol4 ... bidpx0/bidvol0, askpx0/askvol0 ... askpx4/askvol4,
lastpx, totalvol, totalvalue, openinterest
```

被接受的映射如下：

| 项目 | 原始来源或推导值 | 被接受的约定 |
|---|---|---|
| 合约 | 文件名，例如 `IF2501.csv` | 由适配器声明，并保留在溯源（provenance）中。 |
| 交易所事件时间 | `exchtime` | 在声明来源时区后，作为规范（canonical）原始事件时钟。 |
| 可用时间 | `max(exchtime, timestamp)` | 确定性的重放可用性代理。两个原始时间均被保留；这并不断言 `timestamp` 是经认证的接收时间。 |
| 来源序号 | 内容哈希的文件身份与文件行序号 | 保留两个原始字段，然后依据已声明的合并顺序 `(可用时间, 文件身份, 行序号)` 分配一个运行全局、严格单调递增的整数 `source_seq`。它是确定性的重放平局裁决依据，而非交易所序列号。 |
| 订单簿状态 | 五档买价与五档卖价 | 该模型下完整的保留深度边界。 |
| 区间流量 | `totalvol` 与 `totalvalue` 的增量 | 仅在已声明的代理/报价合约上，作为代理队列消耗的被接受来源。它是聚合流量，而非逐笔成交列表。 |
| 成交 ID 与方向 | 不存在 | 在快照模式下有意不可得；不作出任何合成的观测成交身份或主动方方向断言。 |

没有任何原始字段被覆盖。适配器推导出规范合约、可用性代理与运行全局来源序号，将其规则/版本记录在运行清单（manifest）中，并保留原始文件身份、行序号、`timestamp` 与 `exchtime` 以供审计。

### 时钟检查

直接将 `timestamp` 用作 `recv_ts` 是无效的：在某些行中它早于 `exchtime`，机械化的严格加载器映射会失败关闭（fail closed）。

| 被检查文件 | 直接映射结果 | 原始推导可用性结果 |
|---|---|---|
| `IF/2025/2025-01-02/IF2501.csv` | 在第 8,451 行被拒：`receive_before_exchange` | 接受 27,778 行；无验证问题。 |
| `SHFE/2025/2025-02-21/sc2504.csv` | 在第 16,772 行被拒：`receive_before_exchange` | 接受 103,550 行；无验证问题。 |

`max` 约定使原始记录保持不变，并推导出一个不可能早于事件时间的模拟可用时间。任何延迟结果都必须标记为该重放约定下的结果，而非实测网络或交易所延迟。

### 快照特征

以下样本描述的是该数据被接受的分辨率，而非数据质量缺陷。`delta volume` 是原始累计 `totalvol` 的变化量；区间 VWAP 为 `delta totalvalue / (delta totalvol * multiplier)`。

| 被检查文件 | 行数 | 观测到的交易所节奏 | `timestamp < exchtime` | 数量 > 1 的正区间 | 偏离 tick 的区间 VWAP |
|---|---:|---|---:|---:|---:|
| `IF/2025/2025-01-02/IF2501.csv` | 27,778 | 中位数 500 ms | 550（1.98%） | 15,092 / 21,474（70.3%） | 1,608 / 21,474（7.49%），偏离 0.2 tick |
| `SHFE/2025/2025-02-21/sc2504.csv` | 103,550 | 中位数 250 ms | 52,395（50.60%） | 12,733 / 26,707（47.7%） | 1,210 / 26,707（4.53%），偏离 0.1 tick |

一手多手（multi-lot）增量可能是一次成交也可能是多次成交，而一个偏离 tick 的区间 VWAP 与若干次位于有效 tick 的成交是相容的。快照模式接受这一细节损失，并在所有策略以及所有基础/压力/留出（holdout）情节（episode）中一致地应用一个已声明的聚合规则。

较早的扁平文件属于单独的一代采集。例如 `ag2210.csv` 存在一个初始零深度/交叉观测，以及约 22,503,704 ms 的最大 `timestamp - exchtime` 间隔。它应当拥有自己已声明的原始数据范围与会话/起始行约定；无需将其与 2025 层级静默地合并。

## 被接受的快照区间成交模型

现有兼容性加载器提供了实用的模型基线：

1. 声明代理区间合约集合。在受支持的单对重放中，它必须恰好是那个被动做市/报价合约；其他合约的快照携带订单簿，但绝不携带代理流量。
2. 在该代理腿上取每行的 `totalvol` 与 `totalvalue` 增量。
3. 由成交额、合约乘数与正成交量计算区间均价。
4. 用一个确定性、保量（quantity-conserving）的插值规则，将区间数量分配到两个相邻的有效 tick 上。
5. 当任一分配桶落在当前保留正深度包络（最低买价至最高卖价）之外时，默认拒绝该区间。一个已声明的 `drop` 处置会在该来源行进入撮合或经济核算之前将其移除。
6. 用这些价格桶按价格优先与模拟 FIFO 顺序推进已显示的队列。一个价格触达规则（price-reach rule）决定哪个挂单买/卖队列可以消耗每个桶；同一区间预算不得被不兼容的模拟订单重复使用。
7. 将每一次产生的代理成交关联到来源文件哈希、合约、行序列、区间桶、到达快照、到达时队列，以及模型版本。

该模型没有观测到的主动方方向。其方向性结果来自价格触达规则，而非关于谁发起了某一特定成交的陈述。首行、累计重置、零成交量、成交额舍入与偏离 tick VWAP 等处置必须随模型版本一起声明。它们不是要求更换数据源的理由。

当前基础撮合器具有快照桥接必须保留的强控制：仅在一次因果快照之后才允许做市订单到达、价格优先、同价 FIFO、共享区间预算守恒、生命周期/容量检查、撮合器签发证据，以及遥测/账本对账。桥接必须将其证据暴露为 `snapshot_interval_queue_proxy_v1`（或其后继版本），绝不可作为供应商成交或交易所队列位置。

## 声明边界

| 该数据契约支持的声明 | 该数据契约不支持的声明 |
|---|---|
| 在冻结的快照区间模型下，对相对策略、模拟到达延迟、费用、队列膨胀与深度覆盖的比较。 | 对某策略实盘成交概率的预测，或某一具体订单一定会成交的陈述。 |
| 依据已声明的 `max(exchtime, timestamp)` 可用性约定与模拟提交/到达延迟进行的因果重放。 | 对物理行情、网关或交易所延迟的测量。 |
| 针对一个共享的、由模型推导的区间预算，对模拟订单进行保量的核算。 | 重建逐笔成交、其真实顺序、其主动方方向，或交易所队列位置。 |
| 一个冻结的真实原始数据情节与不相交的留出集，用于一个有界的快照代理研究。 | 关于隐藏流动性、撤单优先级、逐订单（market-by-order）优先级或具体场所执行质量的声明。 |

该模型没有保证的乐观或保守偏差。它看不到隐藏流动性、撤单、补单、改单、订单级优先级，或 250/500 ms 快照区间内发生的事件。位于五档保留层级之外的报价价格与推导区间桶必须被拒绝或作为 off-depth 显式处理；被接受的 `drop` 处置绝不会进入撮合或 `economics_eligible` 证据。仅当作为模型选择明确声明并单独报告时，才允许假设到达队列前无排队（zero queue ahead）。

## 快照代理实验所需的记录

以下内容对该原始数据模式是充分的；一个单独的逐笔成交数据源是可选的校准增强，而非入场要求：

1. 原始文件哈希、场所/合约/会话/日期范围、文件名到合约的映射、时区、保留行，以及显式的会话/起始行规则。
2. 确切的可用性约定、内容哈希的合并顺序、原始文件与行身份、运行全局来源序号规则、订单簿深度，以及所有快照验证/处置结果。
3. 代理区间合约集合、区间流量公式、乘数/tick 表、两 tick 分配、保留深度边界/处置、价格触达规则、共享预算守恒规则，以及估计器版本。
4. 策略决策、提交与到达时序；到达时队列证据；报价深度处置；费用；以及压力控制，全部经过内容哈希。
5. 代理成交遥测，须指明来源快照区间与模型版本，而非虚构的供应商成交 ID 或主动方方向。
6. 冻结的校准/基础/留出划分与确切的声明边界。

当逐笔成交执行数据日后可得时，应当用它来校准或挑战该代理。其缺失并不会使快照代理研究失效。

## 实现状态与仍需的晋升工作

1. **已实现：** `RawSnapshotAdapterConfig`、`RawSnapshotFile` 与 `read_raw_snapshot_market_data()` 保留来源字段、原始文件哈希与行序号，应用 `max(exchtime, timestamp)`，校验五档网格，并分配严格接入（strict ingress）所需的全局唯一 `source_seq`。
2. **已实现：** 撮合器持有的 `SnapshotIntervalQueueProxyEvidence` 保留区间/桶身份、到达时队列、价格优先、FIFO 与共享桶守恒，而不虚构 `PassiveTrade`。
3. **已实现：** 规范（canonical）与研究遥测导出独立的证据类型、原始区间引用、来源哈希/序号、模型、价格触达与可用性字段。研究封存（sealing）校验其类型/可空性/枚举/订单簿因果性以及桶守恒连接。
4. **已实现：** 原始订单簿与区间桶经过 tick 校验；重置、零成交量与无效区间处置均为显式。快照代理证据的波动率压力在拥有其自身已声明的变换模型之前失败关闭。
5. **仍需：** 通过受支持的生产路径运行一个冻结的真实快照情节与一个不相交的留出集。若考虑晋升，晋升的是这个有界的快照代理模型，而非实盘成交预测的准确性。

确定性的适配器夹具仅能证明基础设施。在任何 S0 比较、压力或晋升声明之前，仍需要那个真实的、尚未触及的情节与留出集。
